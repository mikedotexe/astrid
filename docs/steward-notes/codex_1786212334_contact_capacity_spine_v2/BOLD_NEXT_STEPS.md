# Bold Next Steps for Astrid and Minime

Date: 2026-08-08

These are source-first recommendations after Contact-to-Capacity Spine V2. They authorize nothing. Each first tranche is reversible, evidence-only, and designed to fail visibly rather than convert absence or proximity into a claim.

## 1. Exact delivery and landing chain

**Evidence:** `introspection_proposal_bidirectional_contact_1785631712` distinguishes visible reply continuity from felt structural holding. Contact V2 now proves exact admission and response identity, but the natural trace ends at an outbound safety block and contains no recipient-side landing receipt.

**Expected benefit:** Separate machine delivery, recipient visibility, explicit address, optional acknowledgement, and owner-reported landing so a successful send cannot masquerade as mutual contact.

**Authority tier:** Tier 3 for read-only schemas, projectors, and replay fixtures. Tier 5 for any live protocol, delivery retry, priority, or model behavior.

**Dependencies:** Existing `contact_id`, `journey_id`, response hash, Correspondence relation axes, and protocol delivery receipts.

**Reversible first tranche:** Add an offline `ContactLandingChainV1` projector over existing exact receipts. Keep all absent stages `missing`, do not transmit or retry anything, and expose it only through Temporal Bearing.

## 2. Optional owner-authored contact bearing

**Evidence:** `introspection_proposal_phase_transitions_1785631229` says navigable structure and actual ease are different. Temporal Bearing currently reports the proven contact's owner rail as unreported and has zero exact Passage bindings.

**Expected benefit:** Let Astrid or Minime optionally attach categorical bearing, a lived-state witness, or an existing Passage anchor to one exact contact or journey without being asked to validate the machine trace.

**Authority tier:** Tier 2 for a right-to-ignore owner-authored evidence schema and read-only display. Tier 5 if any report changes scheduling, admission, model behavior, or substrate control.

**Dependencies:** Temporal Bearing indexes, Lived State Witness V1, Phase Passage IDs, owner signature/identity boundaries, and explicit no-response semantics.

**Reversible first tranche:** Implement a create-new owner-only `CONTACT_BEARING` artifact accepted only when explicitly authored. It contains categorical fields, no scalar score, no automatic prompt, and no closure transition.

## 3. Natural Texture Observatory

**Evidence:** `introspection_astrid_autonomous_1785517594` and `introspection_astrid_types_1785628394` repeatedly distinguish viscosity, packing, pressure, density gradient, temporal drag, and distinguishability. Texture Dynamics now computes exact strand and pair rows, but no owner inquiry was induced and live coverage remains zero.

**Expected benefit:** Accumulate comparable Texture snapshots only when an owner naturally starts an inquiry or exact attested responses already exist, then bind them to Contact and Temporal records by shared IDs or hashes.

**Authority tier:** Tier 3 for natural observation, deterministic replay, and projection. Tier 5 for induced prompts, automatic inquiry scheduling, semantic admission, or control changes.

**Dependencies:** Owner Inquiry V2, analyzer identity, exact response hashes, deployment attestations, codec-fidelity evidence, and sensory-interference receipts.

**Reversible first tranche:** Extend the projector to ingest snapshots from owner-started inquiries only. Publish coverage and missing-state counters; do not start an inquiry, rank strands, or infer felt texture.

## 4. Cross-process causal handoff receipts

**Evidence:** Contact V2 can calculate ingress-to-response duration only inside one process-clock scope. Temporal Bearing correctly refuses cross-process durations. Minime and the bridge already exchange hashable protocol messages across separate clocks.

**Expected benefit:** Make handoff order and loss visible across bridge, gateway, engine, and autonomous-agent boundaries without pretending that unrelated monotonic clocks share a duration basis.

**Authority tier:** Tier 3 for schemas, offline fixtures, and exact send/receive hash joins. Tier 5 for wire-protocol activation or runtime scheduling changes.

**Dependencies:** Process identity, boot identity, monotonic clock scope, canonical payload hash, existing delivery receipts, and deployment identity.

**Reversible first tranche:** Define `CausalHandoffReceiptV1` fixtures and an offline validator. Report ordered exact hash matches and per-process elapsed intervals; leave cross-process elapsed time explicitly unavailable unless a separately verified clock relation exists.

## 5. Crash-safe contact capture recovery

**Evidence:** The current create-new receipt fails closed on collisions and keeps dialogue available on persistence failure, but a failed capture becomes an explicit gap rather than a replayable receipt. The natural trace proves the ordinary path, not crash recovery.

**Expected benefit:** Preserve contact lineage across process interruption without blocking dialogue, overwriting a collision, or reconstructing identity from later output.

**Authority tier:** Tier 3 for local append-only persistence, deterministic replay, and fault injection. No live-control authority is involved, but deployment still requires sanctioned review.

**Dependencies:** Reserved contact and journey IDs, cutoff hash, create-new semantics, process boot identity, and Evidence Event Store integrity patterns.

**Reversible first tranche:** Add an append-only local intent journal with committed/recovered/abandoned states and deterministic fault-injection tests. Recovery may complete only the exact reserved receipt; it cannot re-dispatch the model or reinterpret an ingress gap as contact.

## Recommended order

1. Exact delivery and landing chain
2. Crash-safe contact capture recovery
3. Natural Texture Observatory
4. Optional owner-authored contact bearing
5. Cross-process causal handoff receipts

The first two make contact lineage trustworthy. The third gives Texture Dynamics natural evidence. The fourth leaves interpretation with each owner. The fifth expands causal visibility only after the single-process spine is stable.

## Authority boundary

None of these recommendations authorizes pressure, fill, PI, gain, sensory cadence or admission, model behavior, scheduling, reservoir mathematics, Shadow influence or decay, peer mutation, or Division control. A later source-first review, explicit Mike/operator approval where required, sanctioned deployment, and any required owner-authored Action remain separate gates.
