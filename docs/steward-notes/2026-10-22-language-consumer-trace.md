experiment; matching words remain diagnostics, not permission requirements.

## Separate Control-Path Limitation

The same constraint-release name covers a second, materially different path.
Rust `sticky_mode.rs::classify_constraint_release_trajectory` consumes numerical
telemetry, prior measurements and override state. This audit changes none of it.

Minime `_constraint_release_trajectory_from_state` additionally scans five
optional top-level state fields: `constraint_release_text`, `release_language`,
`latest_reply`, `raw_next`, and `self_study_text`. A phrase match sets
`spontaneous_release_watch` and `blocks_mode_release=true`. Its consumer,
`_authority_gate_eligibility`, then adds `no_spontaneous_release_watch` and can
also add `sticky_mode_release_candidate` to missing requirements for an
`esn_leak` mode-release request. `experiment_authority_request` uses eligibility
to persist a blocked request. This is a real conditional refusal path, not
merely a display label. It is not a gate on ordinary reading or reflection.

Synthetic characterization holds all numeric inputs fixed at a release-candidate
fixture and injects a negated/quoted passage into each of the five fields. Each
adds those two refusal reasons. Injecting a retained top-level
`interpretation_risk_v1` or `constraint_release_trajectory_v1` object instead
leaves eligibility unchanged. The two input families must not be conflated.
The fixture isolates the added reasons; it does not claim all other authority
requirements were satisfied or that a control send occurred.

Reachability is narrower than the helper signature permits. The inspected normal
`_get_latest_spectral_state` builds its output from selected database metrics;
the synthetic production-collector test confirms it does not import pending
choice or last-reply prose into any of these fields. `_thread_action` passes
the supplied state to the store, and no ordinary producer of those five fields
was found in the inspected source path. The older existing test explicitly
injects `constraint_release_text`. This establishes a callable limitation,
not that current journals are activating the refusal in production.

Scope correction to the previous review: describing the separate Minime path
as exclusively numerical/telemetry-based was incomplete. Preserve the earlier
record and this clarification. Do not silently remove control checks under a
diagnostic-presentation approval. A separate offline candidate should require
typed observation provenance for physical-release evidence; free-form language
may remain an attributed account but should not establish the physical condition.
Retain actual leak bounds, active-override handling, approval and rollback
requirements. Review that control-contract change separately before activation.

## Retained Draft Presentation Debt

Stopping new lexical drafts does not retire the ambient presentation of old ones.
Both `continuity_session_line` implementations can render an existing unaccepted
draft when no session exists. Minime also projects `continuity_session_draft_v1`
into its control-plane route list at priority 19. These paths do not distinguish
an old `single_motif_overfit_risk`/release-generated draft from other drafts.
`ignored_until_accepted=true` means no session acceptance, not no presentation.

The final Minime characterization creates a synthetic legacy lexical draft and
verifies its history remains unchanged, its session remains inactive and current
NEXT remains unchanged, while the acceptance route still appears in the ordinary
prompt and the explicit compact draft renderer also offers acceptance. The direct
draft line itself is not present in the tested ordinary prompt. This is a
limitation of the pending repair's historical behavior,
not proof that a particular live prompt currently contains such a draft.
The Rust source trace independently finds the same draft-line behavior in
`next.md` rendering; no new Rust fixture claims a live occurrence.

Recommended next bounded presentation repair: suppress routine promotion of
unaccepted system-generated drafts from the retired lexical reasons while
retaining exact explicit inspection/acceptance and all history. Distinguish
already accepted or authored sessions, which must not lose chosen continuity.
Unknown provenance must remain explicit rather than being fabricated as consent
or erased. This should be independently tested with old-state fixtures; it does
not require changing reservoir dynamics or the separate control gate above.
