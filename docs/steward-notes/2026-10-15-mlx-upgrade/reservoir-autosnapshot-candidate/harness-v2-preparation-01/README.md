# Private service harness v2: exact initial interpreter transition

This is a source-only revision of the ten Python files from `qualification-harness`. The old source, preparation, test/review receipts and first failed real case remain unchanged. `source-parent-01.json` binds the original copies and retained failure. No prepared sources, active-run state, run directory or accepted numerical evidence were copied here.

The first original/normal case ended before any protocol probe because Python re-executed its already pinned macOS framework runtime: the owned PID and OS start time were unchanged, but argv0 changed from the `.venv/bin/python` launch alias to the exact framework executable. Its child exited naturally with status0. That failed case remains a failure; this revision does not reinterpret it as qualification.

The new boundary checks the actual owned launch command before doing any probe. At readiness, it accepts only that exact command or an initial observation that already shows the pinned runtime, with identical PID, start time and argument tail. The selected executable must equal the prepared interpreter, and every wrapper/runtime hash is recomputed. Readiness must show the exact runtime command. Both raw identities and the derived transition proof are retained. From that point onward, shutdown, listener closure and restore identity comparisons remain strict equality against the raw ready identity. The final receipt verifier independently recomputes the transition from raw identities and binds the runtime to the hash-checked preparation manifest; a claimed transition flag cannot substitute for evidence.

Only `process_identity.py`, `driver.py`, `result_checks.py` and `test_harness.py` change behavior/tests. The service child, persistence/thermostat oracle, fixture, protocol deadlines (2-second open, 5-second receive), matrix reviewer and no-force cleanup policy remain the copied originals. Fake tests add exact-transition success, already-runtime success, and interpreter/hash/argument/PID/start/steady-state/proof-drift refusal.

This directory is not released for real execution. Source review and a root-coordinated guarded stdlib test run are pending. A future real run needs fresh prepared sources bound to these exact harness hashes, a fresh accepted host window, continuous accepted host supervision, and a separate explicit release for each numerical case. No observation, subprocess probe, service import, numerical workload or model run occurs merely by importing the helpers. No production qualification is claimed.
