# Disabled owned recovery fixture

This directory prepares a finite, ordinary-user launchd rehearsal using private generated labels, private files, inert JSON workers, and the unchanged `production-candidate-04` controller, transaction lock, recovery ledger, and one-step driver. `FIXTURE_EXECUTION_ENABLED` is false. Importing modules starts no work; the coordinator CLI refuses execution. No release manifest currently authorizes an OS run.

The main fixture would stop an owned provider during its 11-tick check-in, preserve a second 7-tick handle, restore the private JSON snapshot, and restart the owned workers. Each selected interruption exits only its current owned executor after a durable boundary. Separate subsequent executors perform one exact action or positive evidence reconciliation. Unknown outcomes never authorize repeating debug, signal, bootstrap, evidence production, or a whole transaction. The sole permitted overlap is an adjacent, nonmutating lock holder/refusal pair; every later action waits for both natural reaps.

Ownership and evidence are separate by phase:

- `setup-owner.json`, `setup/`, and `setup.lock` bind the original coordinator, host/boot, exact interpreter family, helpers, generated targets, actual startup identities and returns. A retained uncertain launch may only be adopted from positive current evidence. A reviewed one-successor receipt can authorize exactly one next never-attempted setup action after the previous executor is absent; it preserves the original owner and ledger.
- `controller/`, `recovery/`, execution sessions, Host operation files and phase witnesses retain the exact main protocol. The fixture adapter exposes actual private targets and JSON-only evidence; it does not impersonate production admission or steward authority.
- `cleanup/` has its own context, claims, Host operations and reattachment validation, under the same core transaction lock. It performs a distinct second check-in and proves final state 22/7, exactly two unique check-ins, unchanged main backup 11/7, absent owned jobs/PIDs/listeners and released guards. It never reruns the completed main controller or rewinds its state.
- `pin/` qualifies only a separate one-shot private plist/sentinel boundary. It substitutes one inert model-path argument, never opens a model, waits for natural exit, and removes only the absent, stateless private job. It does not claim execution of the production provider-pinning phase.
- `executors/` retains requests, exact identities, launch intent, raw stdout/stderr, injection acknowledgements and natural exit/reap records. Timeouts retain unresolved evidence and ownership; there is no forced termination or automatic cleanup retry.

`owned_fixture_plan.proposed_schedule()` is the bounded draft schedule, not a run authorization. Cleanup and pin metadata are explicitly initialized after their preceding accepted phase. All source, tests, the fixed worker/hold helper, exact interpreter paths, host binding and frozen core must be bound by an independently reviewed final release. Any later enablement or implementation change requires a new exact-source review and fixture; earlier preparatory results do not transfer acceptance.

Only the coordinating parent agent may release an actual fixture run after its prerequisite reviews and numerical gates. A future real launchd debug operation may require administrator authentication; no administrator command or credential-caching instruction is provided here. The code never broadens that authority to unrelated labels or services.

Current verification is guarded standard-library testing with fake IO. The test runner rejects subprocess creation, signals, sockets, native-library loading and numerical/hardware imports, and hashes the tested source closure before and after. Retained receipts distinguish failures from accepted fake tests. These tests do not establish launchd timing, macOS permission behavior, `ProductionHost` readiness, production restoration, the 14-case service matrix, the 9-case numerical restore qualification, or final-release acceptance. An interrupted partial initial layout before any service claim remains a retained manual-inspection stop; it is not deleted or silently recreated.
